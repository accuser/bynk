## ADR: schema-lock-overlay-channel
title: `bynk.schema.lock` gets its own in/out channel, parallel to `sources`, not folded into it
summary: `CompileOptions::schema_registry` carries pre-read lock content in; `ProjectOutput::schema_lock` carries reconciled content out; `bynk-emit` touches no disk for either direction

**Context.** #1006's Decision C (carried through #1047 into #1078) identified `bynk-emit/src/project/schema_registry.rs` as the one `fs_below_driver` site that couldn't close by relocation alone: unlike `.bynk` source content (`CompileOptions::sources`, #1077/#1081), the schema registry is mid-pipeline, bidirectional, persisted state — read during `run_checks` (its result feeds `emit_unit`'s `schemaVersion`, so it can't simply move to a point after compilation) and written only on a fully clean build. `Sources`/R2.3 as specified (`design/bynk-greenfield-compiler.md`) is scoped to "the compiler's only view of file **contents**" — `.bynk` text specifically — and ADR 0299 (Decision 3) already named the write's atomic-write discipline as a third copy of one pattern in the repo, extraction into a shared helper "not possible without a new crate below `bynk-emit`," and left it as follow-up debt.

**Decision.** Two structurally distinct channels, not one:

- **In:** `CompileOptions::schema_registry` changes type from `bool` to a new `SchemaLock` enum — `Off`, or `On { existing: Option<String> }` where `existing` is the lock file's pre-read content (`None` meaning *verified absent*, a fresh project's first reconciliation). A plain `Option<String>` was rejected: "off" and "on, fresh project" would both spell `None`, and a caller that lost the disk read would still type-check as the latter instead of failing to compile — the two states are kept structurally distinct so that mistake doesn't typecheck.
- **Out:** `ProjectOutput` gains `schema_lock: Option<String>` — the reconciled registry, serialized, whenever the registry was `On`, regardless of whether the content actually changed. The unchanged-content no-op stays where the write is, not in `bynk-emit`.
- `bynk-emit/src/project/schema_registry.rs` keeps every pure function (`reconcile`, `reconcile_one`, the two diagnostic categories, the field-shape snapshot) untouched, and its `read`/`write` become `parse(existing: Option<&str>)`/`serialize(&SchemaRegistry) -> String` — no `Path`, no `std::fs`, no `LOCK_FILE` constant.
- `bynk-driver` gains a `schema_lock` module: `read`/`write`/`lock_path`, ported verbatim from the old `schema_registry.rs` — same temp-file + `sync_all` + rename + directory-fsync sequence, same unchanged-content-is-a-no-op check, same tests. This is deliberately **not** routed through the existing `bynk_driver::atomic_write` (ADR 0299's other pre-existing copy): that helper has no directory fsync and no unchanged-content no-op, and reusing it as-is would silently regress both properties this move is explicitly not allowed to lose. ADR 0299's "third copy... follow-up debt" becomes a fourth, still not extracted — a real shared helper needs a crate below `bynk-emit` that doesn't exist yet, unchanged from that ADR's own conclusion.
- The two production wiring points (`bynk::workers::compile_once`, `bynkc::main::run_compile`'s directory branch) now read the lock file themselves before constructing `CompileOptions`, and write `ProjectOutput::schema_lock` themselves after a successful compile — mechanical, since both already held the project root they need.
- `bynk check` (`check_project`) and the LSP (`analyse_project_with`) continue to hardcode `SchemaLock::Off` — pre-existing behaviour (neither ever reconciled the registry), preserved as-is, not introduced by this change.

**Consequences.** `fs_below_driver` (R2.3's gated probe) drops from 5 to 4 files (`bynk-emit` 3 → 2: `project.rs`'s still-present `use std::fs;` and `project/discovery.rs`, both #1077's much larger remaining scope, stay flagged). `bynkc/tests/events_schema_registry_behaviour.rs`'s acceptance test changes shape (it now does the read-before/write-after itself, mirroring the production wiring) but not outcome — the "a failed build must never perturb the registry" property becomes structural (`Err(ProjectFailure)` carries no content to write) rather than incidental. `bynk-driver`'s `schema_lock` module inherits `schema_registry.rs`'s disk-touching unit tests (round-trip, unchanged-content no-op); `bynk-emit`'s own tests shrink to pure parsing, no temp directories needed. `bynkc/tests/diagnostics_registry.rs`'s `NON_DIAGNOSTIC_LOOKALIKES` loses its `"bynk.schema.lock"` entry — the literal moved out of every crate that scan covers, not just out of production scope within one of them.
