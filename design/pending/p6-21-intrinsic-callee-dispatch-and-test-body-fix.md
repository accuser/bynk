## ADR: intrinsic-callee-dispatch-and-test-body-fix

title: `typecheck_case_body` returns its own `callees` map instead of discarding it — the real fix behind #1247's reverted `Callee::Intrinsic` conversion

summary: Root-causes and fixes the test-body gap #1247 found and reverted around, then re-applies that PR's own conversion now that it's safe

**Context.** #1247 attempted to convert `lower_method_call`'s built-in static-constructor branches to read `Callee::Intrinsic` instead of re-deriving them from a bare receiver name, mirroring the pattern #1245/#1246 already established elsewhere. A full zero-diff bless caught two real regressions — `814_messages_icu_date_styles` and `917_bytes_in_test_case` both emitted an `/* unknown */` placeholder where `Instant.fromEpochMillis`/`Bytes.fromBase64`/`fromUtf8` used to lower correctly. The PR was reverted and the finding documented, but the mechanism wasn't root-caused at the time.

**Root cause, now traced fully.** `bynk-check::test_suites::typecheck_case_body` (the function that re-type-checks a `.test.bynk` `case`/`property` body specifically for the *emit* path, so lowering has full checked-type information) builds its own local `callees: HashMap<ExprId, Callee>` accumulator and threads it through `check_body`'s own `CheckSinks` — the classification is computed correctly. But the function's own signature only ever returned `expr_types`; `callees` was declared, populated, and then silently dropped at the end of the function. Its two real call sites in `bynk-emit/src/project/tests_emit.rs` only ever captured `typed.expr_types = test_suites::typecheck_case_body(...)` — `typed.callees` (a real, `pub` field on `TypedCommons`, sourced from `synthetic_typed_commons_for_target`) was never touched, staying at its default-empty value for every test-case/property body in the project. This is why `cx.commons().callee(e.id)` always returned `None` for a `Bytes`/`Instant` call reached from a test body, even though the exact same call reached from an ordinary handler/service body worked.

**Fix.** `typecheck_case_body` now returns `(HashMap<ExprId, TypedExpr>, HashMap<ExprId, Callee>)` instead of just the first element. Its one purely-diagnostic caller (`check_test_case_body`, inside `bynk-check` itself) already discarded the return value (`let _ = ...`) and needed no change. Its two real consumers in `bynk-emit/src/project/tests_emit.rs` now destructure both: `(typed.expr_types, typed.callees) = test_suites::typecheck_case_body(...)`.

With `typed.callees` now genuinely populated for test-case bodies, `lower_method_call`'s static-constructor branches (`List`/`Map.empty`, `Int`/`Float.parse`, `Duration.millis`, `Instant.fromEpochMillis`, `Bytes.*`, `Stream.of`) are re-converted to read `Callee::Intrinsic { ns, op }` — the exact change #1247 reverted, now safe. As with the earlier storage-field/agent-construction conversions, this closes a real latent gap beyond just "cleaner code": `List`/`Map`/`Duration`/`Instant`/`Bytes`/`Stream`'s own emitter-side guards never checked `cx.is_local(&id.name)` at all (unlike every other branch converted in this track), while the checker's own `ctx.lookup(X).is_none()` guard — present before every one of these `Callee::Intrinsic` insertions in `calls.rs` — is strictly more correct. `Int`/`Float` are lexically reserved (never locally shadowable), so their own conversion is for consistency rather than closing a real gap.

**Consequences.** Verified by a full zero-diff bless against the entire `bynkc` e2e fixture corpus, including the exact two fixtures (`814_messages_icu_date_styles`, `917_bytes_in_test_case`) that caught the original gap — both now lower identically to before, confirming the `Callee`-driven path is reached and correct inside test bodies too. `ast_importers` unaffected. `lower_method_call`'s remaining branches (held-map ops, agent-method dispatch, the `HttpResult`/`QueueResult`/`Events.emit` gap, the kernel-method fallthrough) are still untouched — this is another bounded increment, not the full P6.21 cutover.
