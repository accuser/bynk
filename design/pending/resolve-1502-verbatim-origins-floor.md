## ADR: verbatim-origins-floor-at-retirement
title: verbatim_origins's argued floor is 1, matching the live probe exactly — the one surviving variant traces to verbatim_sites' own two already-permanent sites
summary: Only NotYetConverted has a real production construction site; Contracts/Secrets/RuntimeUse are dead in production, confirmed by direct grep, matching §9's own prior finding

**Context.** §5 named `verbatim_origins`'s retirement bar as "an argued floor, expected small
(1–3), named file-by-file at retirement the way `ast_importers`'s floor of 5 was" — but that
naming was never done. The probe has read 1 for some time (since well before #1486's own
`verbatim_sites` capstone), inside the expected range, but §12 (Retirement) still just repeated
"`verbatim_origins` reads its own argued floor" without ever producing one. #1501 (landed, PR
#1504) settled `ts_writes`'s own floor at 809, leaving `verbatim_origins` as the one probe
standing between this track and §12's own three-probe retirement bar.

**Decision.** Confirmed directly, not assumed: every `VerbatimOrigin::` construction site in the
workspace (`grep -rn "VerbatimOrigin::" --include=*.rs .`), cross-checked against
`xtask/src/greenfield_status.rs`'s own `verbatim_origins_violations` (scans `bynk-emit/src/**/*.rs`
only, excludes `#[cfg(test)]` ranges and comments, counts distinct `VerbatimOrigin::<Variant>`
names referenced). `VerbatimOrigin` (`bynk-ts/src/program.rs:1876`) has exactly four variants:
`Contracts`, `Secrets`, `RuntimeUse`, `NotYetConverted`. Only two real, non-test construction sites
exist anywhere in `bynk-emit/src`, both `NotYetConverted`: `project.rs:2480`
(`adapter_bindings[name].content`) and `project.rs:2509` (`emitter::emit_runtime_module()`) — the
identical two sites `verbatim_sites`' own floor of 2 already argues permanent (ADR 0399, confirmed
unchanged by #1486): foreign, user-authored TypeScript and a committed npm build artifact, neither
ever generated by `bynk-emit`. `Contracts`/`Secrets`/`RuntimeUse` have zero production callers —
every remaining reference is a `bynk-ts` unit-test fixture (`bynk-ts/src/program.rs`/`printer.rs`),
which the probe's own `test_mod_ranges` exclusion already discounts. This isn't a new finding:
§9's own "Risks" section already recorded it, from P7.8/#1313's own grounding work — Arc C's
originally-named first-slice trio (`contracts.rs`/`secrets.rs`/`runtime_use.rs`) turned out not to
need `bynk-ts` conversion at all, since none of the three ever build `TsProgram`-shaped output.
This issue formalises that existing finding into the argued-floor writeup §5/§12 require, rather
than re-deriving it.

The dead-variant question (§9's own "removing them is separate, later cleanup, out of scope
here"): kept, deliberately, matching that precedent exactly. Not required for `verbatim_origins`
to retire at its own floor — a variant with zero production callers doesn't move the probe's
count, only a real construction site does, so removing the three dead variants is orthogonal
cleanup, not a retirement blocker.

**Consequences.** `verbatim_origins`'s own retirement bar (§12) is met: the argued floor (1)
matches the live probe exactly, the same shape `ts_any` (26, #1459/#1460), `verbatim_sites` (2,
ADR 0399/#1486), and `ts_writes` (809, #1501) already closed at. All three of §12's own gated
probes now read their own argued floor — the retirement PR itself (removing
`design/tracks/the-typescript-tree.md`, appending its closing summary to
`../archive/retired-tracks.md`, closing #1293) is tracked separately as #1503, with nothing left
blocking it after this issue.
