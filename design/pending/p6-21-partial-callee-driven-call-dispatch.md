## ADR: partial-callee-driven-call-dispatch

title: `lower_call`'s agent-construction and sum-variant-construction branches read `Callee` instead of re-deriving it — a bounded first step on P6.21, not the full cutover

summary: Converts the two branches of `emitter/lower.rs`'s `lower_call` that already have real `Callee` backing, leaving the two that don't (`HttpResult`/`QueueResult` bare-variant construction, `Events.emit`) on their existing `Ty`-based path until a real checker-side design decision gives them one

**Context.** A scoping pass into P6.21 (the completion plan's proposed real P6.2 cutover) found two things: the plan overstated what `bynk-emit::ir::lower` already has (only `Callee::Ctor` is rendered anywhere in the IR pass; every other `Callee` variant is passed through unrendered, so a full "render TS from `IrExpr::Call`" rewrite would need building that render layer from scratch), and left open whether P6.21 should be (a) a surgical swap of each dispatcher branch's own receiver/name-detection test for a `Callee`-classified one, keeping every existing TS template, or (b) the larger rewrite. A follow-up safety probe (P6.23's own investigation) independently confirmed `HttpResult`/`QueueResult` bare-variant construction and `Events.emit` have **no** `Callee` recorded for them at all — Decision C (#1143) deliberately excluded them, and `GlobalRef`'s own doc comment in `ir.rs` already documents why: the checker's own disambiguation for these is contextual/position-dependent (`expected`/`ctx.return_ty` peeling), with no sink recorded anywhere a later reader can read back without re-deriving the same contextual logic — the exact duplication the `Callee` precedent exists to avoid.

**Decision.** Resolve the (a)/(b) question by doing (a) first, incrementally, only where it's actually safe today: `lower_call`'s two branches that already have real `Callee` backing.

1. **Agent construction (`AgentName(key)`)** — was guarded by `cx.local_agents.contains(&name.name) && args_lowered.len() == 1`, a name-matched re-derivation of what the checker's own `Callee::AgentInit(String)` (P6.0) already resolved once. Now: `matches!(cx.commons().callee(e.id), Some(Callee::AgentInit(_)))`. The arg-count access (`args_lowered.first()`) keeps an ADR 0334-style panic rather than blind indexing, in case a future `AgentDecl` shape ever admits more than one key field — the checker already guarantees exactly one on any certified program today.
2. **Sum-variant construction (`Won(prize)`)** — was guarded by `call_is_sum_variant(cx, type_name, &name.name)`, a name-matched string comparison against the call's own checked `Ty::Named` (with a `type_name != &name.name` guard defending against a false match `Callee::Ctor` makes unnecessary — it's only ever assigned when the checker is certain this is a real variant construction). Now reads `sum.name.name`/`tag` straight off `Callee::Ctor { sum: Arc<TypeDecl>, tag: String }`. `call_is_sum_variant` is retired — its one call site is gone.

Both are real instances of R6.5's own named defect class (a name-matched receiver/callee test that could misfire on a shadowed or colliding name) — not just a refactor for its own sake, the same correctness upgrade `body_writes_state`/#1196 already delivered for `Callee::Store`.

**HttpResult/QueueResult bare-variant construction and `Events.emit` are deliberately untouched.** No `Callee` classification exists for them (confirmed independently by both the P6.21 and P6.23 scoping passes) — converting them would mean either adding a checker-side "sink" recording the contextual disambiguation decision explicitly, or re-deriving that same logic inside `bynk-emit`, the exact duplication this precedent avoids. Left as a real, separate, cross-crate design decision (tracked alongside P6.23's own blocker on the identical gap), not attempted here.

**`lower_method_call` (the larger, ~20-branch, ~900-line dispatcher) is untouched.** This slice is a bounded, verifiable first step — not the full P6.21 cutover the completion plan originally scoped in one piece.

**Consequences.** Verified by a full zero-diff bless against the entire `bynkc` e2e fixture corpus (`bless_positive_fixtures`/`positive_fixtures`/`negative_fixtures`/`no_unknown_placeholder_in_emitted_output`, all passing with no generated-output changes) — the `Callee`-driven read produces byte-identical dispatch decisions to the name-matched code for every real construct the corpus already covers. `ast_importers` unaffected (this file was already counted). A future slice can extend this same pattern to `lower_method_call`'s own Callee-backed branches, and a separate future slice (needing real checker-side work) can close the `HttpResult`/`QueueResult`/`Events.emit` gap once a real classification sink exists.
