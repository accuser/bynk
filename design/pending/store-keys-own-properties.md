changelog: "Store collection keys named after `Object.prototype` members now behave like any other key (#1685). A store `Map`, `Set` or `Cache` is a plain object at runtime, so `items.put(\"__proto__\", 1)` was silently dropped (an object value reassigned the record's prototype, adding phantom keys), and `contains`, `get` and `upsert` read an inherited name such as `constructor` or `toString` as present. Keys often come from request input. Membership now uses `Object.hasOwn`, and a write that may create a key defines it (`Object.defineProperty`). This applies to every store op, held connection maps, and `@indexed` posting lists, where a field value of `constructor` or `__proto__` threw a `TypeError`. The query `groupBy`, `joinOn` and `leftJoin` helpers, which crashed on the same keys, now hash into null-prototype objects. The stored shape is unchanged. Proved at runtime by the behavioural fixture `1685_store_keys_prototype`; the baseline fixture now has no expected failures."
