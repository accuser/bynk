changelog: "An expected type now flows from the other operand of `==`/`!=` (#1659): `o == None`, `None == o`, `r == Ok(7)` and `r != Err(\"x\")` are accepted. They were `cannot_infer_…`, or inside a `suite`, an `Ok`/`Err` read an unrelated `Result[(), ValidationError]`. A `let` annotation now decides what `Ok`/`Err` builds over the enclosing return type, so `let r: Result[Int, String] = Ok(1)` in a handler returning `HttpResult` is no longer `ambiguous_constructor`. Every diagnostic a `suite` or integration suite raises now carries its file, line and span; they used to render as a bare `[code] message` (#696). Separately, a store `Set`'s element and a store `Map`'s or `Cache`'s key must be value-keyable: `String`, `Int`, or a refined or opaque type over them (`bynk.store.unkeyable_key`, #1680). A record there was accepted and then failed `tsc`, since a store collection is keyed by its key's string form."
