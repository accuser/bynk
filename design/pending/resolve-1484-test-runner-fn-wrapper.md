changelog: Resolves #1484 — the five near-identical `async function {name}() { ... }` test-generation wrappers in `bynk-emit/src/project/tests_emit.rs` (`emit_test_case_function`, `emit_test_property_function`, `emit_test_history_property_function`, `emit_contract_attack_function`, and `emit_integration_module`'s own inline case wrapper) now build their outer function declaration as one real `bynk_ts::TsStmt` via a single shared construction, `async_test_runner_fn` (a real `TsDecl::Function`: no generics, no params, no return-type annotation, never exported — exactly matching the pre-existing hand-templated `format!("async function {name}() {{\n")` shape), instead of five separate hand-templated wrappers. Each function's own inner content (a `try`/`catch`, or a flat statement sequence ending in a `return`) stays one opaque `TsStmt::raw` — matching `emit_free_fn`'s own established `TsDecl::Function` + `Raw`-body precedent (#1480) — not decomposed further: the interior already mixes real node prints (`bynk_ts::print_stmt` calls already scattered through each caller) with genuinely-opaque lowered bodies (`lower.rs`'s permanent exclusion, ADR 0391) at this track's own established per-file indentation convention (statements directly inside these generated functions render at a fixed 4-space depth regardless of real AST nesting depth — confirmed by reading the printer's own `render_block_stmts`/`TsDecl::Function` arms directly, not assumed); decomposing the wrapper's interior into a fully-real tree per site would risk silently changing that baked-in indentation for 3 of the 5 sites (property/history-property/contract-attack have no `try`/`catch`, so their direct-body statements would render one level shallower than today's actual bytes under the printer's own normal nesting math). `emit_test_case_function`'s own `case_smb` (the one real, still-merged per-case source map) and `emit_integration_module`'s own inline case (which now builds a local per-case buffer/map instead of writing straight into the module's own `out`/`module_smb`) carry a real `nested_map`, merged automatically by the printer per #1477; the other three carry none, matching their own pre-existing "deliberate scope cut" (property/history/contract-attack bodies are collaborator-free predicate scaffolding, already unmapped before this change). `emit_contract_attack_function` returns `Option<TsStmt>` (`None` for its defensive, in-practice-unreachable non-`Free`-fn branch — its own caller already filters to `FnName::Free` before calling); every other converted function returns a bare `TsStmt`. A review-caught-during-implementation correctness note: `TsDecl::Function`'s own printer arm adds exactly one trailing `\n` after its closing brace (`render_block_stmts` itself ends with a bare `}`, no newline) — NOT an extra blank-line separator as a first draft of this conversion assumed; each caller still needs its own explicit blank-line push between generated functions, restored at all four call sites after a real `tsc_verify`/e2e-fixture failure caught the regression directly (missing blank lines between generated test-runner functions), not left to be caught by golden-diff alone. Review of #1497 (before merge) caught two further items, both addressed: (1) the property/history-property/contract-attack call sites printed their returned `TsStmt` through a plain `bynk_ts::print_stmt`, which silently drops a `nested_map` — a latent footgun given `async_test_runner_fn`'s own `nested_map` parameter, even though all three always pass `None` today; both sites now route through `bynk_ts::print_stmt_and_merge` uniformly, matching the other two call sites, closing the class of mistake rather than just the current instance. (2) `emit_integration_module`'s own inline case wrapper changed its source-map wiring shape, not just its position (staging each case's body map in a local `case_smb` under a placeholder source id before the printer's own `nested_map` merge re-tags it to the real per-case `src_id` at print time) — nothing in the suite pinned that the re-tag still lands each case under its own `.bynk` file, so a new test, `system_suite_case_maps_to_its_own_bynk_source` (`bynkc/tests/source_map_bodies.rs`), pins it directly: a two-file `system` suite (two participant contexts, one case per file, identical line numbers in both files so a same-line-wrong-file regression can't slip past), asserting each case's own call/expect lines resolve to its own source id. Verified: `cargo test -p bynk-emit` (187/187), `cargo test -p bynkc --test source_map_bodies` (6/6, including the new test), and the full `cargo test --workspace` (all green, byte-identical fixture output via the `tsc_verify` corpus and the `bynkc` e2e positive-fixtures suite). `ts_writes` (gated probe) moves 822 → 817 — the five retired `format!("async function {name}() {{\n")` call sites.
