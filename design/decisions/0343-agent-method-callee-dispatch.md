# 0343 — `lower_method_call`'s two agent-invocation branches read `Callee::Agent` instead of re-deriving it from `cx.local_agents`/`cx.local_agent_vars`

- **Status:** Accepted (v0.248.11)

summary: Continues P6.21's own incremental pattern into the agent-handler-dispatch branches, closing the same name-matched-receiver defect class already closed for storage fields, agent construction, and sum-variant construction

**Context.** Two of `lower_method_call`'s branches dispatch an agent handler call: `Agent(key).method(args)` (receiver is a fresh `Call` expression) and `x.method(args)` after `let x = Agent(key)` (receiver is a bound `Ident`). Both were guarded by a name-matched lookup — `cx.local_agents.contains(&name.name)` for the first, `cx.local_agent_vars.contains_key(&id.name)` for the second — re-deriving what the checker's own `Callee::Agent{agent, handler}` (P6.0) already resolved once. The checker records this classification (`checker/calls.rs`'s own agent-handler-dispatch arm) purely from the receiver's *checked type* resolving to a declared agent's own named type — uniform across both AST shapes, and across the self-agent WebSocket-transfer special case (`cx.ws_self_agent()`) nested inside the first branch's own body, none of which needed separate handling to convert.

**Decision.** Both guards now read `matches!(cx.commons().callee(e.id), Some(Callee::Agent { .. }))` instead of the name-matched lookup. The let-bound branch's own body still consults `cx.local_agent_vars.get(&id.name)` — that answers a genuinely different question (*which* agent this bound name refers to, needed for `record_agent_call`'s bookkeeping and the `#908` rename-resolution the branch already handles) than the one `Callee` now settles (*is* this receiver really an agent instance at all — the same "receiver-name-matched vs. checker-classified" distinction every other branch converted in this track already drew).

**Consequences.** Verified by a full zero-diff bless against the entire `bynkc` e2e fixture corpus — byte-identical generated output for every fixture, confirming the `Callee`-driven read reproduces every dispatch decision the name-matched code made, including the self-agent WS-transfer sub-case. `ast_importers` unaffected. `lower_method_call`'s remaining branches (held-map ops, the `HttpResult`/`QueueResult`/`Events.emit` gap, the kernel-method fallthrough) are still untouched.
