# 0338 — `is`'s real IR desugar builds only what `lower_is` itself constructs — a forced-temp Block plus a boolean test, not R5.9's separate narrowing-binding machinery

- **Status:** Accepted (v0.248.6)

**Context.** `design/tracks/the-ir.md`'s own P6.4 row (#1157) deferred both `Is` and R5.9/R5.10 together, under one "Decision D" note: "R5.9's scope-recording and R5.10's forced-temp are properties of `is`'s own future `IrExpr`/`IrStmt` construction." Read at face value, that groups the two as one combined prerequisite for `Is`'s own lowering. Tracing the shipped desugar (`emitter/lower.rs`'s `lower_is`) directly found otherwise: `lower_is` itself constructs exactly two things — a forced receiver temp (`is_receiver_ref_forced`, R5.10) and a boolean test (a JS expression string, never a narrowing *binding*). The narrowing binding R5.9 describes (`const n = <temp> as Quantity`, scoped into a following `if`/`&&` branch) is applied *separately*, by `gather_is_bindings_for_emit` at the `&&`/`if` call sites that consume `is`'s own boolean result — not by `lower_is` itself. R5.9's own rationale text confirms this reading independently: it names the memoization hazard (`is_binding_cache`, keyed by span) as living in the checker's own `collect_is_bindings`, applied "at exactly two sites, `&&`/`implies` right operands and an `if` then-block" — sites `Is`'s own lowering never reaches.

**Decision.** `Is` lowers fully in this slice — a `Block` wrapping one forced-temp `Let` and a tail boolean expression, reusing P6.4's already-shipped `IrPat`/`lower_pattern_ir`/`variants_of` machinery for the boolean test rather than re-deriving pattern structure by hand. Two sub-decisions:

1. **A bare `is Name` where `Name` names a declared refined type is a different check from `is Variant(...)`** — the two are syntactically identical (a bare name after `is`) and only the checker's own type information (`Ty::Base`/`Ty::Named{kind: Refined, ..}` on the operand, plus whether `Name` resolves to `TypeBody::Refined`) disambiguates them, mirroring `is_refined_is_check` exactly. The refined case constructs a new `IrExprKind::RefinedCheck{value, base, refinement}` — `refinement: Option<Refinement>` reused verbatim from `bynk_syntax::ast`, the same "reused, not adapted" posture `IrPat::Refined` (P6.4) already committed to for the identical payload (a closed, finite `PredKind` set — `InRange`/`MinLength`/`Matches`/…), not an open-ended expression tree R6.7's "desugar once" mandate would object to. Decomposing `PredKind` itself into `BinOp`/`Call` primitives is real, separate, deferred work.
2. **Every other pattern shape routes through `lower_pattern_ir` (real since P6.4, never wired until now) plus a new recursive boolean-test walk, `lower_pattern_test_ir`** — the IR-native sibling of `emitter/lower.rs`'s own `pattern_match_tests`, ported rather than duplicated: same recursive shape (one test per structural constraint, AND-joined), same skip-irrefutable-payload rule, but reading `IrPat`'s own already-resolved `fields`/`scrutinee_ty` (via `variant_info_of`) instead of re-deriving a positional field's name the string emitter's own `positional_field_name` needs.

R5.9's own cross-site narrowing-binding-propagation machinery — a genuinely separate, still-open design question spanning `&&`/`implies`/`if`, not `Is` alone — is named here as unsettled, not silently dropped: the same "R5.9's scope, correctly attributed away from this slice" finding this track's own P6.3/P6.14/P6.19 corrections already made for their own rows.

**Consequences.** No shipped emitter path reaches `lower_expr_ir`'s `Is` arm yet (same dormant posture as `Question`, P6.15). Verified by four unit tests covering a declared-refined-type check, a bare variant tag test, a nested-variant test (proving the field path is rooted at the resolved payload field, not the bare receiver), and an or-pattern. Zero-diff bless confirmed regardless. A future slice building R5.9's own narrowing-binding machinery can consume this slice's `Is` lowering directly — the forced-temp `Local` this function's own `Block` introduces is exactly the value such a binding would need to reference.
